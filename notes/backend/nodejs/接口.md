# 数据接口API

## API是什么？

Application Programming Interface(应用程序编程接口)，实现前后端之间的通信，后端向外提供的一套可以被调用的能力，以及前后端双方约定好的调用方式。

## 从前端的角度如何理解接口？

我怎么调用？传什么？能得到什么？

API = 后端提供给我的“数据入口/功能入口”。

`GET /api/users`

## 从后端的角度如何理解接口？

API 是“我对外提供的能力”

后端需要关心的事情就比较多

- URL / 路由
- GET / POST / PUT / DELETE
- 参数
- 参数校验
- 权限
- 业务逻辑
- 数据库
- 返回数据
- 错误码
- 异常处理
- 性能
- 安全

```text
GET /api/transactions
 ↓
Express Router
 ↓
Controller
 ↓
Service
 ↓
MongoDB
 ↓
查询 transactions
 ↓
组装 JSON
 ↓
res.json(...)
```

## 总结

```text
                 API
                  │
        ┌─────────┴─────────┐
        ↓                   ↓
     前端视角              后端视角
        │                   │
   我要用户信息          我提供用户查询能力
        │                   │
   怎么调用？             接收什么参数？
        │                   │
   返回什么？             怎么处理？
        │                   │
   怎么展示？             去哪里查数据库？
                            │
                         返回什么？
```
